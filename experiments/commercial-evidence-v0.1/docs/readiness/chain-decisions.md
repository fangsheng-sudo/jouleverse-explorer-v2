# 商业应用接入：请链方确认的最小问题集

这是待答复问题单，未代替任何个人或机构声明授权。本文件尚未通过工具发送给维护者；由项目方选择合适沟通渠道。

| 问题 | 建议答复形式 | 未答复时的处理 |
|---|---|---|
| 1. 现有商业摘要存证/更正/撤销方案能否复用？ | 合约/协议文档与已审核源码链接；若无，请确认是否接受新方案审阅 | 不新建或部署主网合约；接口保持草案 |
| 2. 接入所信任的网络检查点及确认/重组规则是什么？ | 可追溯检查点来源、最小确认数、异常处置及是否有正式最终性说明 | 只展示观察；不给“最终确认”结论 |
| 3. 应用注册、写入、更正和撤销由谁授权？ | 应用命名空间、角色、授权/撤销流程；是否支持代理执行 | 保持只读，不把智能体只读授权当写权限 |
| 4. 商业合约的可信部署清单是什么？ | network、address、runtime code hash、deployment block、ABI版本、源码构建、是否代理及权限治理 | draft清单字段留null，门禁blocked |
| 5. 一次更正/撤销对当前状态有什么严格含义？ | 前驱是否必须存在、记录唯一性、允许分叉吗、撤销是否终态、重签发方式 | 不把日志存在包装成当前业务有效 |
| 6. 谁支付费用，是否有赞助额度？ | 费用来源、预算、失败成本、限额与人工审批；不使用原生J普通转账 | 不承诺免费锚定，不开发自动充值 |
| 7. RPC历史日志、限流和试验环境如何使用？ | 允许的范围/频率、节点接口、历史可用性、隔离测试方式 | 继续每轮8块的本地模拟；不全链扫描 |
| 8. Explorer与独立服务如何交付？ | 页面入口和审核范围、索引运行方、部署责任、版本与回滚确认方式 | 试点留个人独立分支，不加入生产运行路径 |

首次沟通优先回答1–4，形成一份最小书面决定；5–8可在实现审查前补齐。任何决定都记录日期、适用范围和来源引用，不凭私人聊天截图或未经授权署名替代。
