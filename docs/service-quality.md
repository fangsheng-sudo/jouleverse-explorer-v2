# 第 9 项：Jouleverse 接入服务质量评估 V1

`evaluateServiceQuality(window, targets, probes, nowMs)` 让接入方按同一口径评估单个服务，例如一个只读节点端点或一个证据核验接口。它消费已有探针记录，不负责发请求、运行定时器、发送告警或存储历史。可接入现有监测系统，无需另建一套探针。

- 每个服务、观察位置和探针策略单独统计；窗口左闭右开，必须已结束且能整除为固定时段，最多 10,000 个时段。采集方提供每个时段一个最终结果：成功、超时、失败。缺报单列，不能当成功；重复、错位或越界记录拒绝评估。
- 覆盖率 = 已观测时段 / 应观测时段。可用率下界按「缺报全失败」计算，上界按「缺报全成功」计算；是否达标用精确比例判断，报告中的上下界向外取整。目标用基点表示，10,000 等于 100%。
- 第 95 百分位耗时采用最近秩法，仅统计成功耗时。超时和失败计入可用率，不混入成功耗时；只有成功样本数量达到策略门槛才判断延迟达标。
- 覆盖率和观测数先达门槛，才判断是否异常。可用率上界低于目标、或有足够成功样本且延迟超标，判为异常。可用率下界与延迟都达标，判为达标。其余为观测不足，不能解除告警。
- 运营方判断恢复时，应使用同一服务和策略下相邻的完整窗口：前窗异常、本窗达标，才能报告「本窗口恢复达标」。持续恢复和告警去抖应由上层按连续窗口配置。

本版不新增依赖、不接触链上资金，不对主网可用性作任何承诺。上线前需要实际采集、明确定义探针成功条件和超时、隔离采集端故障，并确认阈值及告警责任人。单节点、单地点观测不能代表整条链。
