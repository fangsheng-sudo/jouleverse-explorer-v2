# 第 8 项：Jouleverse 智能体授权检查 V1

接入方可用 `authorizeAgentRequest` 按租户、智能体、链、操作、资源及有效期判定是否开放一次请求。默认拒绝；只支持 Jouleverse（3666）。不替代现有 Agent 钱包的签名策略、合约校验和预算。

| 操作 | 授权绑定 | 成功结果 |
|---|---|---|
| 交易回执核验 | 单个交易哈希 | 允许查询 |
| WJ 付款核验 | 单个交易哈希，单独授权 | 允许查询 |
| 手续费补给预检 | 单个目标账户 | 允许查询 |
| 合约调用复核 | 发起账户、目标合约、完整 calldata 的 Keccak-256 摘要；原生 value 必须为 0 | 仅可送审 |

请求方不能自报身份或提供生效授权。接入方须从已认证会话取得租户与智能体，从受控授权存储读取当前授权、从可信时钟取时间。有效区间包含起点、不包含到期点；撤销状态不放行；重复授权编号按歧义处理。不要把授权判定当作可缓存的通行证。

把判定放在实际调用前，向下游传递同一份已核验输入，不要重新使用未经校验的请求参数。补给预检的补给钱包和额度从运营方配置读取；此授权只允许预检，不能申请资金。调用复核必须绑定完整参数；相同函数名、不同收款人或金额不能复用授权。原生 value 为 0 也可能通过合约移动 WJ 或其他资产，因此「仅可送审」绝不表示已批准签名。

本模块无网络、钱包、数据库、签名、广播或依赖新增。授权规则本身可重复判定，未实现身份认证、持久化授权管理、单次审批消费、防重放、额度计数、策略执行服务或生产接入。上线前须在服务端执行检查并另做审批、撤销生效、幂等及审计；浏览器判定不构成服务端访问控制。

## 实际只读分发入口

`createAgentReadGateway({ loadGrants, handlers, now, timeoutMs })` 将检查绑定到真实调用。每次从受信存储读取当前授权，在业务 handler 前重新按可信时钟检查撤销、有效期、租户、资源及操作。输入主体与调用参数在 await 前复制，handler 只接收已授权的规范化资源；结果附 request、bindingHash 与 checkedAtMs，便于审计同一份请求。bindingHash 是完整性标识，不是签名或可重放的授权凭证。

handlers 仅支持 verify-receipt、verify-wj-payment、inspect-gas。review-contract-call 只返回 executed:false，绝不进入钱包、签名或广播接口。默认整体截止 5 秒、最多两个底层操作；超时发送 AbortSignal，不响应的操作继续占用槽位，原始异常脱敏。调用方须从已认证的会话取得 principal，不能直接接受请求正文声称的身份。

授权在检查后仍可能被撤销，读取适配器和策略存储仍是可信边界；跨进程撤销一致性、持久额度和一次性审批消费不由本只读网关提供。它不能部署在不可信浏览器中充当服务端安全边界。模块独立于 #3，无新增服务或依赖；未来可由受信后端把 handler 接到 #3/#4/#7，但不得把 review-only 解读为交易获批。
