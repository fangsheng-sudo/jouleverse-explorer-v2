# JNSVote 使用教程

本文档面向两类用户，分别说明如何在 JNSDAO 治理投票中完成自己的工作：

- **普通用户**：参与投票（投赞成 / 反对票）
- **多签签名人**：创建投票提案（可视化界面，走多签确认流程）

> 入口：工具集 →「🗳️ JNSVote 治理投票」，或直接访问 `/jnsvote`。

---

## 一、参与投票（普通用户）

### 1. 投票资格

同时满足以下两点，才有投票资格（页面顶部会以 ✅/❌ 实时显示）：

- **持有 JTI 认证**（JTI 余额 > 0）
- **持有 JNS 域名**（JNS 持仓 > 0）

资格由合约在投票时强制校验；不满足时前端按钮会置灰并提示「无投票资格」。

### 2. 投票步骤

1. **连接钱包**：点击页面「🔗 连接钱包」，选择 MetaMask 等钱包。
2. **切换到 Jouleverse 链**：若钱包不在目标链，投票时会提示手动切换。
   - Chain ID：`3666`
   - RPC：`https://rpc.jnsdao.com`
3. **找到目标提案**：在提案列表点击任意「进行中」状态的提案卡片，进入详情页。
4. **投票**：在详情页点击「投赞成票」或「投反对票」，钱包弹出签名确认。
5. **等待上链**：确认后等待交易入块；成功后页面显示「已投票」，并自动刷新票数。

### 3. 投票规则（重要）

- 只能在提案**进行中**（当前区块 ∈ (开始区块, 结束区块)）时投票。
- 每个地址对每个提案**只能投一次**，重复投票会被合约拒绝。
- 投票成功后，地址会自动铸造 1 枚 **JNSVote SBT 徽章**（不可转移的参与证明，可在页面「投票徽章」区查看）。
- 票权按该地址持有的 **JNS 总量**计入代表持仓统计。

### 4. 常见错误提示

| 提示 | 含义 |
| --- | --- |
| 已取消投票 | 你在钱包里拒绝了签名 |
| 提案尚未开始投票 | 当前区块早于开始区块 |
| 提案投票已结束 | 当前区块晚于结束区块 |
| 您已投过票，无法重复投票 | 该地址已投过此提案 |
| 您未持有 JTI，无投票资格 | 缺少 JTI 认证 |
| 您未持有 JNS 域名，无投票资格 | 缺少 JNS 域名持仓 |

## 二、多签人创建提案（可视化）

> 本功能**仅对多签签名人可见**。普通投票者看不到治理面板（前端按 `isOwner` 结果隐藏，非签名人零额外链上负担）。

### 0. 试用提案（本次上线自带示范）

为便于验收投票功能，本次上线附带一个**试用投票提案**，供签名人照此创建、普通用户试投票：

- **提案标题**：是否同意本链上投票工具进行正式部署
- **详情链接**：可留空，或指向正式提案文档（支持 `https://` / `ipfs://`）
- **开始区块**：须晚于当前区块，建议留约 1 小时缓冲（≈ 240 块）
- **结束区块**：开始区块 + 约 7 天投票期（≈ 40320 块）

> 区块约 15 秒/块，表单会实时把区块高度换算成「≈ N 天后」帮助判断；请以创建时的当前区块为准重新计算。

### 1. 前提

JNSVote 合约的 `createProposal` 是 `onlyOwner`，而 owner 是一个 **2/3 多签钱包**：

- 多签地址：`0x4eF599b6E39D950D6Ddbd830fF5f95e06770C1B3`
- 签名人：Koant (J-0)、剪云为裳 (J-37)、明海云 (J-7)
- 确认门槛：**2 / 3**

因此创建提案必须走多签流程，任何一个签名人都可以发起。

### 2. 创建流程（三步）

**第一步：任一签名人发起（提交即成为首个确认人）**

1. 用签名人账户连接钱包，进入 `/jnsvote`。
2. 页面出现「🛡️ 治理端（多签签名人专属）」面板。
3. 在「📝 创建新提案」表单填写：

   | 字段 | 必填 | 说明 |
   | --- | --- | --- |
   | 提案标题 | ✅ | 提案的标题，如「批准 X 项治理决议」 |
   | 提案详情链接 | 否 | 指向完整提案文档的链接（支持 `https://` 或 `ipfs://`） |
   | 开始区块 | ✅ | 须 **> 当前区块**（表单会实时显示换算后的约几天后） |
   | 结束区块 | ✅ | 须 **> 开始区块** |

4. 点击「提交创建（成为首确认人）」。钱包签名后，一笔多签交易被提交（`submitTransaction`），**提交者自动成为首个确认人**。

**第二步：其余签名人确认**

1. 另一个签名人进入治理面板，在「⏳ 待确认的治理交易」列表看到这笔「创建提案」交易。
2. 核对交易参数（类型、标题、链接、开始/结束区块、原生金额为 0）无误后，点击「确认」（`confirmTransaction`）。

**第三步：确认数达标后执行**

1. 当确认数达到门槛（2/3，即 2 人）时，交易状态变为「可执行」。
2. 任一签名人点击「执行」（`executeTransaction`），交易上链，提案正式创建成功。

> 注：当确认数恰好达到门槛时，确认操作可能直接触发执行（由多签合约语义决定），签名前请务必核验参数。

### 3. 注意事项

- **区块时间约 15 秒/块**：表单会把区块高度换算成「≈ N 天后」帮助判断；请为多签确认和入块预留充足时间。
- **只能在开始前操作**：创建提案要求开始区块晚于当前区块；开始后无法修改、禁用或重新启用（前端会阻断，见「管理已有提案」）。
- **确认可能立即执行**：当确认数恰好达到门槛时，确认操作可能直接触发执行，签名前请务必核验参数。
- **保留交易哈希**：广播后请保留哈希；回执未确认前不会重复发送，可点「查询已广播交易回执」恢复。
- **管理已有提案**：签名人还可通过「管理已有提案」对未开始的提案执行「修改 / 禁用 / 重新启用」三类操作，流程同为多签提交 + 确认 + 执行。

## 三、提案结果判定规则（背景知识）

提案结束后，页面会显示「通过 / 未通过」。判定规则随提案编号分界：

| 规则 | 适用提案 | 支持率（ar） | 代表率（rr） |
| --- | --- | --- | --- |
| V1 | 提案 id ≤ 2 | > 2/3 | > 1/2 |
| V2 | 提案 id ≥ 3 | > 2/3 | > 0.4 |

- **支持率 ar** = 赞成票数 / (赞成票数 + 反对票数)
- **代表率 rr** = 赞成票代表 JNS 持仓量 / JNS 总量快照

两项同时满足才算「通过」。
