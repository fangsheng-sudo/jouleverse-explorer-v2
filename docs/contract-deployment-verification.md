# 合约部署档案与代码核验

依赖 #66 的合约目录。目录打开及展开档案不联网；点击「只读核验链上代码」才向配置节点发起只读请求。核验顺序为：检查网络编号 → 按固定高度读取基线区块并核对区块哈希 → 读取当前最新区块高度 → 读取指定地址在该高度的运行时代码。最多 4 次只读 RPC 请求，无自动重试、钱包签名或交易。若网络编号或基线区块哈希不符，立即停止后续查询。

初始基线由配置节点 https://rpc.jnsdao.com 在网络编号 3666、区块 8584399（十六进制 0x82fccf）返回的字节码生成。采集前后该高度区块哈希一致。区块哈希和三份 Keccak-256（代码摘要）记录在部署核验模块，适用于 WJ、JNSVote 和创世金库多签。每次核验都会重新读取固定基线区块并比对哈希，避免仅展示一个未参与核验的基线哈希。

结果解释：
- 「与观测基线一致」：当前代码摘要与登记摘要一致，且基线区块哈希通过核对。
- 「与观测基线不一致」：当前代码摘要与登记摘要不同；可能是代码变化，也可能是代理合约实现等因素，需人工复核。
- 「基线区块哈希不一致或无法确认」：停止核验，不对当前代码作匹配判断。
- 「暂无比对基线」：地址代码已读取，但没有该地址的登记摘要。
- 「无代码 / 网络不符 / 查询失败」：分别显示，不混同为核验通过。

观测基线仅供检测代码变化。相同网络编号不能独立证明链身份；匹配摘要不证明源码、审计、权限、代理实现、可用性或业务安全。未取得可信证明前，源码版本、部署交易、管理和升级权限、停用状态均标记为未核实。此核验最多 4 次 RPC 请求，全部只读；维护者仍需独立核实 RPC 节点可信性和合约治理信息。
