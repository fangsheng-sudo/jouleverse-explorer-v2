# 第 7 项：Jouleverse 手续费补给预检 V1

给智能体和生态接入方判断：目标钱包是否缺少原生 J；如需补充，独立的补给钱包是否同时持有足量 WJ 和支付补给交易所需的原生 J。目标账户只有 WJ 时，不能把 WJ 余额当作它能直接付手续费的依据。

## 接入

调用 `inspectGasReplenishment(publicClient, policy)`。补给钱包与目标地址应来自运营方配置；所有金额用最小单位 bigint，1 J / 1 WJ 各对应 10¹⁸ 最小单位。先设置触发余额、补齐目标、单次 WJ 释放上限、补给钱包的原生 J 费用额度及保留额。费用额度由运营方给出，不是报价。

| 结果 | 处理 |
|---|---|
| `no-top-up` | 目标原生余额达到触发线，无需补充 |
| `over-cap` | 补足差额超过单次上限，不自动拆单 |
| `insufficient-wj` / `insufficient-sponsor-j` | 分别检查 WJ 库存或原生手续费余额 |
| `review-required` | 在观察高度通过余额检查，提交人工复核 |
| `wrong-chain` / `unavailable` / `invalid-policy` | 停止，核对网络、节点或配置 |

最多五个逻辑只读调用；所有余额查询使用同一观察高度。按高度读取不等同于跨调用锁定区块哈希，重组和在途交易可改变结论；本模块不轮询、不扫描，也不验证合约字节码。每次结果只代表当前观察，不可当作资金预留。

## 复核与上线边界

沿用现有 WJ 工具的 `withdrawTo(recipient, amount)` 路径：补给钱包烧毁自己的 WJ，合约向目标地址释放原生 J，调用自身的原生转账金额应为 0。人工操作前复查网络、账户、目标、金额、余额和待处理请求，用实际发起账户模拟交易并确认手续费在预算内。合约地址可能执行接收逻辑，余额通过不表示释放一定成功。交易后检查回执和目标原生余额；若结果不明，先核对原交易，避免重复补给。

V1 仅提供接入模块，无新增页面、依赖、签名、广播或资金操作。未在主网验证释放交易。真实接入须另做目标白名单、跨请求额度、持久化去重、授权和对账，再考虑自动补给。

## 可靠性与机器接入

第三个参数可设置 `{ timeoutMs, signal }`，默认总截止时间 5 秒，允许 1–30000 毫秒。超时或取消返回 unavailable，停止后续 RPC；已发出的适配器调用不保证立即取消。每个 reader 最多两个未结束底层操作，超过返回 busy；忽略取消的操作仍占用槽位。reader 应关闭自动重试，并为单次请求设置超时。

serializeGasDecision(result) 将 bigint 转为十进制字符串，避免机器接入丢失精度。政策在 await 前复制，不会在观测期间被外部改写。全部金额和链上余额按 uint256 范围检查，不使用 Number 金额。busy/unavailable 均不能作为重试补给交易的依据，只能重试只读预检。

本功能独立于 #3 合并；网络检查仅验证链 ID，不替代独立创世规范、代码核验或对节点诚实性的信任。部署方必须明确节点、合约和政策来源。所有可送审结果仍须人工复核与独立模拟，本模块没有发送交易或自动释放资产的接口。
